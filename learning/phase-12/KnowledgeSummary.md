# Phase 12 Knowledge Summary

最终验收的核心不是“测试越多越好”，而是每个结论都有匹配的证据边界：组件测试证明局部交互，
契约测试证明两端协议，真实 MySQL/Redis 证明数据语义，浏览器 E2E 证明用户主链。替身用于稳定制造
503 和 timeout，但必须明确它不证明真实 DeepSeek、Embedding 或索引质量。

可靠 E2E 还必须可隔离、可重复、可清理：临时容器、随机凭据、独立文件目录、readiness 等待、
显式工具路径和只清理本轮资源。最终四维审计分别回答“能否工作、是否守架构、设计是否合理、
资源能否安全生灭”，并把未知项写成 WARNING，而不是用假成功填补证据空白。

本阶段最有面试价值的证据是：同一条用户链同时验证 HTTP、JWT、MySQL 消息、Redis 幂等 TTL、
Python Envelope 和 Vue 提示；真实数据库与浏览器各自承担不可互相替代的断言。
